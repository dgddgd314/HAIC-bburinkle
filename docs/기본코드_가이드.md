# HAIC 기본 코드 사용 가이드

기준은 2026-11-27에 확인한 로컬 커밋 `052a00b`다. 팀이 구현할 파일은 `src/custom/`에 모여 있다. 아래에서 파일 경로는 별도 표기가 없으면 저장소의 `src/` 기준이다. [원본 README](../README.md)

## 매핑과 위치추정에서 팀이 맡는 부분

- **주어지는 것**은 시뮬레이터 환경, 초기 월드 자세 `(16 m, 11 m, 0°)`, 방과 문의 참고 좌표, 센서 관측, 보행 정책이다. 미션 1에서 당일 지정되는 값은 도착 좌표다. 이후 미션은 직전 종료 위치에서 시작한다.
- **현재 위치를 얻는 경로**는 센서 → 팀의 위치추정 노드 → TF → 미션의 `self.pose()`다. 시작 자세에서 실제 이동량과 회전을 누적해도 위치를 추정할 수 있다. `cmd_vel()`은 속도 명령이므로 발 미끄러짐이나 회전 오차를 측정해 주지는 않는다.
- **지도 활용 예시**로 공개된 벽·문을 월드 좌표의 선분으로 표현하고 LiDAR 관측을 대조해 누적 오차를 보정할 수 있다. 또는 연습 때 센서로 점유 격자 지도를 한 번 만들고 저장해 대회 때 재사용할 수 있다. 지도의 원점이 시작점이면 월드 기준 목표를 지도 좌표로 변환해야 한다. 절벽 리스폰처럼 위치가 순간적으로 바뀌면 위치추정도 재초기화한다.
- **규정과 구현 제안의 경계**가 중요하다. 규정집 29쪽은 Mapping·Localization·Navigation 코드를 제출 항목으로 적는다. 전체 건물 실시간 SLAM이나 `.pgm` 파일 형식을 명시하지 않는다. 공개 좌표만으로 지도를 생성해도 Mapping 요건을 충족하는지는 문서에서 확인되지 않는다. 현재 기본 코드에는 팀용 지도나 위치추정 노드가 등록돼 있지 않다. [대회 규정집](./%5B로인공%5D%20final_competition_rulebook.pdf) · [공개 좌표와 센서 설명](../README.md#4-미션)

## 팀이 작성할 파일과 함수

| 파일 | 현재 동작 | 팀이 구현할 내용 |
|---|---|---|
| `custom/bringup.launch.py` | `generate_launch_description()`이 빈 `LaunchDescription`을 반환한다. | 미션 사이에도 계속 돌아갈 위치추정·주행 노드 등을 등록한다. 미션마다 새로 생성되는 객체 밖에 위치추정 상태를 유지할 수 있다. |
| `custom/planner/planner.py` | `plan(instruction)`은 현재 `NotImplementedError`를 발생시킨다. | 영문 명령을 읽어 순서대로 미션 번호 또는 (번호, 인자 사전)을 반환한다. 예: `[(2, {"color": "blue"}), (1, {"goal": [15, 8]})]`. |
| `custom/mission_1/mission_1.py` | `Mission1.run()`이 미션을 시작하고 목표와 시작 위치를 출력한다. | 명령의 월드 좌표로 이동해 골반이 목표 반경 0.5 m 안에서 정지하도록 한다. |
| `custom/mission_2/mission_2.py` | `Mission2.run()`이 목표 색을 읽어 출력한다. | 카메라로 해당 색 콘을 찾아 문 쪽 0.75 m 앞의 목표 영역에 정지한다. |
| `custom/mission_3/mission_3.py` | `Mission3.run()`이 미션을 시작하고 추락 횟수를 읽는다. | 입구부터 절벽 구간을 거쳐 출구 밖으로 이동하고 리스폰 뒤 경로를 다시 잡는다. |
| `custom/mission_4/mission_4.py` | `Mission4.run()`이 빈 방 목록을 반환한다. | VLM으로 세 방을 판별하고 교실로 이동한다. `self.result(rooms=answer)`에 북→남 순서로 `classroom`, `medical`, `cafeteria`의 실제 배치를 담는다. |
| `custom/mission_5/mission_5.py` | `Mission5.run()`이 미션을 시작하고 결과 객체를 반환한다. | Panda 카메라 관측으로 팀이 학습한 조작 정책을 실행해 연필을 꽂고 그리퍼를 연다. |
| `custom/mission_6/mission_6.py` | `Mission6.run()`이 미션을 시작하고 결과 객체를 반환한다. | 센서로 공을 찾고 밀거나 차서 골대에 넣는다. |
| `custom/sensors.yaml` · `custom/walking.yaml` | 전자는 G1·Panda 센서 배치, 후자는 G1 보행 정책 및 속도 상한을 설정한다. | G1은 제공 ONNX 정책으로 걸을 수 있다. 보행 정책 교체는 선택 사항이다. |
| `custom/requirements.txt` · `custom/ros_packages.txt` | 설치 스크립트가 팀 의존성을 읽는다. | 각각 Python 패키지와 apt/ROS 패키지를 기록한다. |

각 미션 클래스의 `__init__()`은 현재 부모 노드를 초기화한다. 센서 구독과 상태 초기화는 여기에 두고, 동작을 수행하는 `run()`은 결과를 반환하도록 작성한다. 실행기가 미션 노드를 ROS executor에 등록하고 정리한다.

## 미션 안에서 사용할 함수

모두 [mission_api.py](../src/mission_api.py)의 `Mission` 메서드·속성이다.

| 호출 또는 속성 | 효과와 반환값 |
|---|---|
| `self.begin_mission(n)` | 해당 미션의 물체를 초기화하고 활성화 응답 사전을 받는다. G1은 현재 위치에서 시작한다. |
| `self.params` | 플래너가 이번 미션에 넘긴 사전. 대회 모드에서는 미션 1의 `goal`과 미션 2의 `color`를 여기서 읽는다. |
| `self.latest(topic, msg_type, timeout=5.0)` | 처음 호출할 때 구독하고 첫 메시지를 기다린다. 이후에는 캐시를 즉시 반환하므로 같은 측정값을 다시 받을 수 있다. 아직 수신하지 못하면 `None`이다. |
| `self.pose(frame="map", child="pelvis", timeout=2.0)` | TF에서 요청한 프레임 기준의 `(x, y, yaw)`를 읽는다. 단위는 m, m, rad. 변환을 찾지 못하면 `None`이다. 위치를 추정하는 알고리즘은 팀 노드가 제공해야 한다. |
| `self.cmd_vel(vx, vy, wz)` | 몸체 기준 전진·왼쪽 속도(m/s)와 반시계 회전 속도(rad/s)를 한 번 발행한다. 주행 중에는 반복 발행하며, 명령이 0.5초 동안 끊기면 정지한다. |
| `self.stop()` | 속도 세 성분이 0인 명령을 발행한다. |
| `self.last_status()` · `self.wait_for_sim(timeout)` | 각각 마지막 상태 사전 조회와 시뮬레이터 상태 수신 대기. 첫 상태 수신 전 조회는 `None`, 대기 시간 초과는 `MissionTimeout`이다. |
| `self.respawn()` · `self.gap_falls` | 리스폰을 요청해 응답을 받거나, 절벽 추락으로 자동 리스폰한 누적 횟수를 읽는다. |
| `self.log(text)` · `self.result(**data)` | 메시지를 출력하거나 실행기에 돌려줄 `MissionResult`를 만든다. 성공 판정은 실행 후 심판이 한다. |
| `self.m1_goal` · `self.m2_color` · `self.m4_rooms` | 앞의 둘은 연습용 목표·색이며 대회 명령 모드에서는 `None`이다. 마지막 속성은 방 이름 목록이다. 실제 방 순서는 VLM으로 판별한다. |
| `self.randomize()` · `self.judge(n)` | 각각 연습용 무작위 배치 요청과 실행기용 판정 요청. 대회 규칙상 팀 미션 코드에서 두 함수를 호출하면 안 된다. |

**위치추정에 쓸 입력**은 `/lidar/points`의 3차원 점군, `/imu`의 각속도·가속도, `/joint_states`의 관절 상태 등이다. IMU 메시지에 완성된 자세가 들어 있지는 않다. 카메라는 `/camera/color/image_raw`와 `/camera/depth/image_raw`에서 읽는다. Panda 조작에는 별도 카메라와 `/panda/eef_delta_command`, `/panda/joint_command`, `/panda/gripper_command`가 있다. `--ground-truth`의 정답 `/odom`은 디버깅 전용이다.

## 실행과 판정 흐름

| 파일 | 호출과 역할 |
|---|---|
| [main.py](../src/main.py) | `main()`이 실행 모드를 선택한다. `start_simulator()`가 MuJoCo를 띄우고 `start_robot_state_publisher()`가 로봇 링크 TF를 위한 프로세스를, `start_bringup()`이 팀 launch를 시작한다. `make_plan()`은 팀 플래너 출력을 검증해 (번호, 인자) 목록으로 정규화한다. `mission_class()`가 해당 클래스를 찾고 `run_step()`이 인자를 설정해 `run()`을 호출한 뒤 정지·판정·정리를 진행한다. |
| [mission_api.py](../src/mission_api.py) | `MissionRunner.start()/finish()/close()`가 미션 노드의 등록·제거·실행기 종료를 담당한다. `check_result()`는 반환 형식을 정리한다. `GapFallWatch`는 허용 추락 횟수 초과를 감시한다. `run_standalone(MissionN)`은 이미 실행 중인 시뮬레이터에서 미션 하나를 실행하고 판정한다. |
| [referee.py](../src/referee.py) | `Referee.begin()`이 측정을 시작하고 `finish()`가 시뮬레이터 판정과 반환 데이터를 모은다. `totals()`는 전체 결과를 집계하고 `close()`는 기록을 마감한다. `default_results_path()`는 결과 JSON 경로를 정한다. |
| `web/instruction_page.py` | `main()`은 영문 명령 입력 화면, `show_progress()`와 `show_record()`는 진행 상태와 단계별 기록을 표시한다. |
| `main_config.yaml` · `scenarios/*.yaml` · `tools/make_scenario.py` | 각각 실행·판정 설정, 배치 데이터, 시나리오 생성 도구다. 대회 미션이 무작위 배치나 목표 정답을 읽는 입력으로 사용하면 안 된다. |
| `setup/install_ros_deps.sh` · `setup/install_conda_env.sh` | Ubuntu 22.04/ROS 2 Humble 기준으로 ROS·시스템 의존성과 conda/Python 환경을 각각 설치한다. 기본 환경 사양은 `setup/env.yml`, 기본 Python 패키지는 `setup/requirements.txt`에 있다. |
| `ros2_bridge/run_g1_ros.py` · `ros2_bridge/tools/ros_publisher.py` | 시뮬레이터와 ROS를 연결한다. `SimPublisher.publish_lidar()/publish_imus()/publish_camera()`가 센서 데이터를 발행하고 `_on_cmd_vel()`이 속도 명령을 받는다. |
| `environment/robots/control/g1/teleop_wasd.py` | 키보드로 G1에 속도 명령을 보내는 연습 도구다. 기본 보행과 센서 출력을 팀 미션 구현과 별도로 확인할 수 있다. |

실행은 저장소의 `src/`에서 한다. 센서·TF 디버깅에는 `python main.py --sim-only`, 단일 미션 연습에는 `python main.py --missions 1`, 영문 명령부터 평가까지는 `python main.py --llm-web`을 쓴다. 팀 플래너와 미션 동작은 구현 전이므로 기본 코드만으로 미션을 해결하지 않는다.
